# 订单列表查询迁移测试计划（MyBatis XML → JPA Specification）

状态：草案。第 7 节的问题需要你确认，确认前不开始搭回放设施。

## 1. 思路

- 验收标准就是老实现本身：同一请求、同一份数据，新实现的响应必须与老实现一致，包括行数、顺序、分页元数据、字段值、异常响应。没有文档可对照，所以用差分测试，不另写预期值。
- 生产日志回放是主力，但日志只能覆盖出现过的请求。日志没触发的 SQL 分支、日志对应不到的数据形态，用第 5 节的补充用例兜底。
- 比较对象是老实现在同一快照上现跑的结果，不是日志里记录的历史响应，因为数据早已变化。

## 2. 范围

- 范围内：参数绑定、过滤、排序、分页与总数、返回字段映射与序列化、异常响应、数据权限和租户等隐式条件、性能。
- 范围外：订单写接口、详情接口、前端。老实现代码不改。

## 3. 阶段

| 阶段 | 做什么 | 完成标准 |
|---|---|---|
| P0 澄清 | 回答第 7 节问题，拿到日志样本和快照方案 | 问题清零 |
| P1 行为盘点 | 读 XML、Mapper、Service、Controller、MyBatis 插件与拦截器、序列化配置，填盘点表（见 order-list-diff-rules.md 第 1 节） | 每个条件分支和隐式行为都有一行 |
| P2 同跑设施 | 同一请求同时调用新旧实现并比对，两者读同一库同一快照，关闭缓存 | 手工制造 3 个差异，比对器都能报出 |
| P3 日志回放 | 脱敏、解析、按参数形态分层抽样，先小样本冒烟再全量 | 全量回放完成，差异全部进入分诊 |
| P4 补充用例 | 覆盖日志未触及的分支和数据边界（第 5 节） | 盘点表每一行至少被一个用例命中 |
| P5 差异分诊 | 按 order-list-diff-rules.md 第 2 节分级，逐条给处置 | 无未分诊差异 |
| P6 影子比对与灰度 | 生产只读双跑采样比对，通过后按比例切流，保留回滚开关 | 影子期内 A、B 类差异为零，性能达标 |
| P7 下线老实现 | 观察期结束后删除 XML 与开关 | 回滚窗口结束 |

## 4. 回放设计要点

- 日志字段：需要请求参数、身份信息（用户、租户、角色，数据权限靠它）、请求时间。有历史响应更好，但只作参考，不作比对基准。
- 脱敏：回放前对手机号、地址等脱敏，且脱敏后不能改变过滤的命中结果，关键字类查询的值要保持可命中。
- 时间：含相对时间的查询（如近 7 天）回放时固定时钟，或按日志时间换算成绝对区间，两边用同一个。
- 分层抽样：按参数形态分组（出现了哪些过滤字段、值的类型、排序字段、页码区间），每组保底抽样，不用纯随机，避免长尾形态被淹没。
- 只读保证：确认老实现没有写副作用（访问计数、审计、缓存回填）。有则在回放环境隔离。
- 数据：新旧读同一快照，记录快照时间，快照要覆盖日志窗口对应的数据。

## 5. 补充用例（日志之外）

- 每个过滤字段 x {不传, null, 空串, 纯空格, 典型值, 边界值, 特殊字符}。
- 模糊查询里的 % 和 _；大小写与库的 collation。
- 数值 0、负数、枚举非法值；日期开闭区间、跨天、时区。
- IN 条件：空列表、单元素、超长列表。
- 排序：默认排序、排序字段非法、排序键并列。
- 分页：首页、末页、越界页、页大小为 0、超上限、负数，页码从 0 还是 1 开始。
- 数据形态：一对多 join 产生重复行、软删除、左连接缺失、空字段、超长文本、大数据量页。
- 异常：非法参数时老实现返回的状态码和错误体，新实现要一致。
- 数据用 Testcontainers 的 MySQL 灌固定种子数据，库版本与生产一致。

## 6. 退出标准（阈值待你确认）

1. 行集合、total、异常响应类差异必须清零，不能豁免。
2. 顺序、字段格式类差异都有书面处置。
3. 盘点表每一行都有命中记录（回放或补充用例）。
4. 性能：p95 延迟与每请求 SQL 条数不劣于老实现，幅度由你定。
5. 影子期时长与样本量由你定。

## 7. 待确认问题

1. 日志有哪些字段？有没有用户、租户、角色身份，请求时间，历史响应？是 access log 还是应用层请求日志，有无请求体？（阻塞 P0）
2. 回放环境：能拿到脱敏的生产库副本，还是只能在生产上做只读影子比对？（阻塞 P2）
3. 同跑方式：同一进程内用开关调用新旧两个实现，还是两套实例各自回放再比对？我倾向前者，需要你确认。
4. 回放发现老行为本身是 bug（比如 status=0 被当成没传）时，新实现先保持一致、修正另行发版，还是迁移时一并修？我倾向先一致，由你拍板。
5. 排序键并列时老实现的顺序本来就不稳定，这类顺序差异算不算缺陷？
6. 性能阈值（p95、SQL 条数）、影子期时长、样本量。
7. 真实代码在哪个目录？拿到后才能把盘点表填实，目前只是排查清单。

## 8. 已知风险

- 日志窗口之外的低频行为（季度、年度活动期）回放覆盖不到，需要业务方补充清单。
- 日志里没有的身份组合（特殊角色、跨租户）会漏掉数据权限类差异。
