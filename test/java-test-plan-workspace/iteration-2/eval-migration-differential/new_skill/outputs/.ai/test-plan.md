## 1. 需求拆解
### 1.1 用户流程
- 调用方带筛选条件、分页、排序调用订单列表接口，拿到订单列表（是否同时返回 total：待查）。对外接口不变，调用方无感。
- 基线说明：老实现（MyBatis XML 手写 SQL）线上跑了 3 年，团队自己说不清全部历史行为。因此「行为正确」的定义是「与老实现的实际输出一致」，文档和直觉都不能当基线。

### 1.2 验收标准（需求明写）
- AC-1 对外接口不变：请求参数、响应结构、分页、排序、错误码。
- AC-2 新实现不改行为：用生产流量日志回放，新旧输出对比，每条差异要有裁决。

### 1.3 业务规则（需求明写）
- 需求只写了「迁移、接口不变」，没有写具体的筛选和排序规则。这些规则全部藏在老 XML 和入参处理里，需要从目标项目代码提取。当前没有代码，待查（见第 2 节 Q1）。

### 1.4 推导规则（需求没写，不阻塞评审，由评审人决定是否纳入）
以下是手写 SQL 迁到 JPA Specification 时最容易悄悄改变的行为点。老实现具体怎么做必须查 XML，查到之前不下结论：
- D-1 条件组合：条件间 AND/OR 关系；空串、null、空集合入参是否忽略（对应 XML 里 `<if test>` 的判断口径）
- D-2 模糊匹配：LIKE 通配符转义、前缀/后缀/双侧模糊、大小写（取决于库的 collation）
- D-3 区间：时间、金额区间的开闭、只传一端、起止颠倒、时区
- D-4 排序：默认排序、多列排序、NULL 排序位置、同值行顺序是否稳定、非法排序字段怎么处理
- D-5 分页：页码从 0 还是 1 起、越界页、pageSize 为 0、负数、超上限、total 的算法
- D-6 关联与去重：join 一对多造成的重复行，XML 里是否 DISTINCT 或子查询，JPA 侧是否一致
- D-7 隐含过滤：软删除、租户、数据权限条件是否在 XML 里写死
- D-8 字段映射：枚举/状态值、日期格式、金额精度、空值在响应里是 null 还是缺省
- D-9 性能：耗时、SQL 条数、N+1（迁移默认纳入，见第 4 节）

## 4. 差分测试设计
### 4.1 输入来源
- 生产流量日志：只回放查询类请求，脱敏后只在测试环境使用。日志是否含老响应、是否已脱敏、覆盖范围，待 Q3。
- 日志里即使有老响应，也不直接当基线：日志产生时的数据和测试库不同，基线一律用老实现在同一份测试数据上现跑。
- 日志覆盖不到的组合，由 DIFF-02（随机）和 DIFF-03（定向边界）补。

### 4.2 双跑方式
- 同一份测试数据、同一个数据库快照，新旧实现各跑一遍，逐请求对比。数据来源待 Q4，老实现基线怎么搭待 Q6。
- 固定时钟：条件里有「最近 N 天」「今天」这类相对时间的，两边用同一个固定时间，否则差异是假的。
- 回放前先扫一遍样本，确认没有带副作用的请求；有的话剔除，不回放。

### 4.3 归一化（只抹掉与行为无关的差异，每条写明理由）
- 允许归一化：JSON 字段顺序、空白符、traceId、服务端生成的响应时间戳。
- 不允许归一化：行顺序、total、null 与字段缺省、数值精度、枚举值、日期格式。这些一变就是行为变了。
- 归一化规则本身随计划评审，评审后不得为了让差异消失而新增。

### 4.4 已批准差异清单（初始为空）
| 编号 | 差异描述 | 触发条件 | 老行为 | 新行为 | 裁决人 | 裁决（改新代码 / 接受变化） | 日期 | 对应测试 |
|---|---|---|---|---|---|---|---|---|
| （空） | | | | | | | | |

- 只有裁决人批准的差异才能入表，清单的变更走评审。
- 未裁决的差异一律算未通过，也不默认判成新代码的问题。
- 老实现不一定是对的：差异只说明变了，是修新代码还是接受变化，由裁决人定，裁决人待 Q1 指定。
- 每条已批准差异要对应一个固定行为的测试，防止之后又悄悄变。

### 4.5 差异处理流程
1. 对跑产出差异报告，按差异模式聚类，每类给代表请求、老输出、新输出和出现次数，不逐条罗列。
2. 裁决人逐类裁决。裁决为改新代码的，修完后重跑全量；裁决为接受的，入 4.4 清单。
3. 同一检查连续 3 轮失败，停下来找人，不继续改。

### 4.6 性能对比（DIFF-05）
- 默认纳入：耗时（p50、p95）、单次请求 SQL 条数、是否出现 N+1。你明确说不需要时再去掉，见 Q5。
- 新旧在同一环境、同一数据量下对比，大结果集样本单独跑一组。
- 阈值待 Q5。阈值定下来之前，该场景只采集数据，不判通过。

### 4.7 数据安全
- 未脱敏的生产数据不得用于回放。
- 差异报告里的请求样本和响应同样要脱敏；日志和报告不打印手机号、证件号等敏感字段；测试代码不硬编码密钥。

### 4.8 通过标准
- DIFF-01 到 DIFF-04：未裁决差异数为 0，所有差异已修复或入 4.4 清单。
- DIFF-05：满足 Q5 阈值。
