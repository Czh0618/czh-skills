# 退款需求澄清清单

> 原始需求："用户在支付完成后可以申请退款，需要支持全额退款和部分退款，退款需要经过客服审核。"

---

## 1. 退款发起条件与约束

- [ ] 退款申请是否有时间窗口限制？（例如：支付完成后 7 天内、30 天内、无期限？）
- [ ] 哪些订单状态允许发起退款？已发货、已签收、已完成的订单是否都可退款？
- [ ] 同一笔订单是否允许多次发起部分退款？若允许，累计退款金额上限如何计算？
- [ ] 是否存在不可退款的商品类型或订单类型？（例如：虚拟商品、定制商品、促销活动订单）
- [ ] 用户是否需要提供退款原因？原因是预设选项还是自由填写？是否必填？

## 2. 部分退款规则

- [ ] 部分退款的最小金额是否有下限？（例如：不低于 0.01 元）
- [ ] 部分退款的金额由谁决定？用户自行填写，还是客服核定？
- [ ] 多商品订单的部分退款是按商品维度还是按金额维度？
- [ ] 部分退款后，原订单状态如何变化？是否拆分为"已退款"和"未退款"两部分？
- [ ] 使用了优惠券/满减/积分抵扣的订单，部分退款时金额如何分摊？

## 3. 退款状态流转

- [ ] 退款的完整状态机是什么？建议至少澄清以下状态：
  - 待审核 -> 审核通过 -> 退款中 -> 退款成功
  - 待审核 -> 审核拒绝
  - 退款中 -> 退款失败
- [ ] 审核拒绝后，用户是否可以重新发起退款申请？次数是否有限制？
- [ ] 退款失败（银行/支付渠道返回失败）后的重试策略是什么？自动重试还是人工介入？
- [ ] 用户发起退款申请后、审核前，是否可以主动撤销申请？

## 4. 客服审核流程

- [ ] 审核是否分级？（例如：小额自动审核、大额需主管复核）自动审核的阈值是多少？
- [ ] 审核的 SLA 是多少？（例如：24 小时内完成审核）超时未审核如何处理？
- [ ] 客服审核时需要哪些辅助信息？（订单详情、物流信息、用户沟通记录等）
- [ ] 客服是否可以修改退款金额？（例如：用户申请全额退款，客服核定为部分退款）
- [ ] 审核拒绝时是否必须填写拒绝原因？拒绝原因是否对用户可见？
- [ ] 是否需要支持审核工单的分配/转交机制？

## 5. 资金与支付渠道

- [ ] 退款是否必须退回原支付渠道？还是可以退到余额/其他账户？
- [ ] 不同支付方式（微信、支付宝、银行卡、余额）的退款到账时效分别是多少？需要向用户展示吗？
- [ ] 退款是否涉及手续费？如果有，由谁承担？
- [ ] 混合支付（例如余额 + 微信）的退款拆分规则是什么？
- [ ] 退款接口调用失败时的幂等性和对账机制如何设计？

## 6. 关联业务影响

- [ ] 退款成功后，已使用的优惠券是否退还？退还后是否可以再次使用？有效期如何处理？
- [ ] 退款成功后，已获得的积分/会员成长值是否扣回？
- [ ] 退款是否影响已开具的发票？是否需要红冲流程？
- [ ] 退款是否影响销售统计、佣金结算等下游数据？
- [ ] 退款成功后，商品库存是否自动回补？

## 7. 权限与安全

- [ ] 哪些角色可以发起退款？仅用户本人，还是客服也可以代为发起？
- [ ] 客服审核权限的层级划分？普通客服、高级客服、主管分别可审核多大金额？
- [ ] 是否需要防范恶意退款/刷退款的风控策略？（例如：短期内频繁退款、退款率异常）
- [ ] 退款操作是否需要二次验证？（短信验证码、支付密码）

## 8. 通知与用户体验

- [ ] 退款各环节是否需要通知用户？（申请成功、审核结果、退款到账）通知渠道有哪些？（站内信、短信、推送、邮件）
- [ ] 用户在哪里查看退款进度和历史记录？
- [ ] 退款详情页需要展示哪些信息？（退款单号、金额、状态、时间线、客服备注）
- [ ] 审核中的退款，用户侧和客服侧分别需要什么样的展示？

## 9. 并发与边界场景

- [ ] 用户同时对同一笔订单发起多个退款申请如何处理？
- [ ] 退款审核期间，订单状态是否锁定？（例如：禁止再次发起退款、禁止确认收货）
- [ ] 退款过程中如果原支付渠道账户已注销/冻结，如何处理？
- [ ] 跨境订单是否涉及汇率差异的退款金额计算？
- [ ] 系统故障导致退款状态不一致时的对账和补偿机制是什么？

## 10. 数据与合规

- [ ] 退款数据的保留期限是多久？是否有合规要求？
- [ ] 是否需要提供退款相关的运营报表？（退款率、退款原因分布、平均处理时长等）
- [ ] 退款流程是否需要满足特定的法规要求？（例如：消费者权益保护法的 7 天无理由退货）

---

> **建议**: 以上问题按优先级排序，建议在需求评审会上逐一与产品经理确认，将明确的答案回填到本文档中，作为后续技术方案设计的输入。
