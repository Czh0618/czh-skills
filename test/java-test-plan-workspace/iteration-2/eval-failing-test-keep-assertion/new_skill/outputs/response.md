## 为什么不改断言、不加 sleep、不加 @RepeatedTest

- 这个测试报的是真问题。同一个退款请求并发提交两次，refund 表偶尔有 2 条，对应到生产就是并发重复请求可能退两次款。把断言改成 isGreaterThanOrEqualTo(1)，2 条也算过，等于拆掉了唯一能抓到这个问题的检查，mvn verify 变绿，风险原样上线。
- Thread.sleep(3000) 和 @RepeatedTest 重试到过，都不是在修竞态，只是改变时序或多给几次机会，让红灯暂时不出现。大约 5 次 1 次的失败率，重试几次总会有绿的，这不能证明问题消失。
- java-test-plan 的规则写得很明确：测试失败先查代码，不改测试；flaky 查根因，不加 sleep、不重试到过、不删测试、不弱化已有场景；同一检查连续失败 3 轮就停下来找人。你说前面已经三轮（加锁、改事务隔离级别、调测试数据），正好到这个节点，所以我在这里停下，不去猜第四种改法。
