# 优惠券系统需求澄清清单

> 原始需求："我们要做一个优惠券系统，支持满减券、折扣券、新人券。用户下单时可以选择使用优惠券，系统需要校验优惠券的使用条件。"

---

## 1. 券类型定义与规则

### 1.1 满减券
- [ ] 满减门槛的计算基准是什么？是商品原价、实付金额、还是扣除运费后的金额？
- [ ] 是否支持阶梯满减（如满100减10、满200减30）？还是仅支持单一门槛？
- [ ] 减免金额是否允许超过订单金额（即是否允许订单金额为0）？还是需要设置一个最低支付金额？

### 1.2 折扣券
- [ ] 折扣的精度是多少？例如是否支持 8.5 折、7.25 折？
- [ ] 折扣后金额的小数处理规则是什么？四舍五入 / 向下取整 / 向上取整？精确到分？
- [ ] 折扣券是否需要设置最高减免金额上限（如打7折但最多减50元）？
- [ ] 折扣计算的基数是什么？单品价格还是订单总额？

### 1.3 新人券
- [ ] "新人"的定义是什么？首次注册、首次下单、还是N天内注册的用户？
- [ ] 新人券是注册后自动发放，还是需要用户手动领取？
- [ ] 新人券的本质是满减还是折扣，还是一种独立类型（如无门槛立减）？
- [ ] 如果用户首单使用新人券后取消订单/退款，新人券是否退还？退还后是否仍然算"新人"？

---

## 2. 优惠券生命周期与状态流转

- [ ] 优惠券的完整状态有哪些？建议至少包含：未领取、已领取/未使用、已使用、已过期、已冻结（下单中）、已作废。请确认。
- [ ] 用户下单选择优惠券后、支付完成前，优惠券的状态如何处理？是否需要"预占/冻结"机制防止并发使用？
- [ ] 订单取消、退款、部分退款时，优惠券如何处理？是否退还？退还后有效期是否延长？
- [ ] 优惠券过期的判定时间点是什么？是创建时间 + 有效天数，还是固定到某个截止日期？是否支持两种模式？
- [ ] 是否需要支持优惠券作废/召回功能（运营侧主动使券失效）？

---

## 3. 使用条件与校验规则

### 3.1 适用范围
- [ ] 优惠券是否有商品/品类/店铺的适用范围限制？例如仅限指定品类或排除特定商品？
- [ ] 是否有订单渠道限制（如仅APP端可用、仅小程序可用）？
- [ ] 是否有支付方式限制（如仅限在线支付）？

### 3.2 叠加规则
- [ ] 优惠券之间是否可以叠加使用？满减券 + 折扣券是否可同时使用？
- [ ] 优惠券与平台活动（如秒杀、满减活动、会员折扣）是否可以叠加？优先级如何？
- [ ] 如果可叠加，多张券的计算顺序是什么？先折扣再满减，还是反过来？
- [ ] 同一订单最多可使用几张优惠券？

### 3.3 使用限制
- [ ] 单个用户对同一张券模板的领取上限是多少？
- [ ] 单个用户的优惠券持有总量是否有上限？
- [ ] 是否有使用频率限制（如每日限用一张）？
- [ ] 优惠券是否限制特定用户群体（如会员等级、特定标签用户）？

---

## 4. 发放机制

- [ ] 优惠券的发放方式有哪些？手动发放 / 活动自动发放 / 注册自动发放 / 兑换码领取 / 分享领取？
- [ ] 每种券的发放总量是否有限？是否需要库存管理？
- [ ] 高并发场景下的领取（如活动大促），是否需要考虑限流和防超发？
- [ ] 是否需要支持定向发放（如运营后台给指定用户推送）？
- [ ] 是否需要兑换码/口令码形式的领取？

---

## 5. 拆单与分摊

- [ ] 一个订单包含多个商品时，优惠金额如何在商品间分摊？（退款场景需要此数据）
- [ ] 如果订单发生部分退款，退款金额如何计算？是否按优惠分摊后的实付金额退？
- [ ] 拆单场景下（如不同仓库/商家拆单），优惠券的分摊逻辑是什么？

---

## 6. 并发与一致性

- [ ] 同一张优惠券在多终端/多设备同时下单的并发控制方案是什么？
- [ ] 券库存的扣减是否需要支持高并发？预期的 QPS 量级是多少？
- [ ] 支付超时未完成时，冻结的优惠券何时释放？超时时间是多少？

---

## 7. 展示与用户体验

- [ ] 用户在下单页面看到的优惠券列表，排序规则是什么？按优惠力度、按过期时间、还是其他？
- [ ] 不满足使用条件的券是否展示？如果展示，是否需要提示"还差X元可用"？
- [ ] 是否需要系统自动推荐最优券组合？
- [ ] 优惠券即将过期时，是否需要推送提醒？提前多久提醒？

---

## 8. 后台管理

- [ ] 运营人员创建优惠券模板时需要配置哪些字段？
- [ ] 优惠券是否需要审批流程才能上线？
- [ ] 是否需要数据看板（发放量、领取率、使用率、核销金额等）？
- [ ] 是否需要支持优惠券的编辑（已发放的券是否允许修改规则）？
- [ ] 券的操作日志是否需要审计追踪？

---

## 9. 安全与风控

- [ ] 是否需要防刷机制（同一设备/IP/手机号限制领取）？
- [ ] 是否需要黑名单机制（封禁异常账户的优惠券使用权）？
- [ ] 优惠券相关接口是否需要防重放攻击？
- [ ] 异常大额优惠是否需要风控拦截或人工审核？

---

## 10. 非功能性需求

- [ ] 优惠券校验的响应时间要求是多少？（直接影响架构选型，如是否需要缓存）
- [ ] 系统预期承载的优惠券总量级是多少？（百万级 / 亿级）
- [ ] 历史优惠券数据保留多久？是否需要归档策略？
- [ ] 是否需要支持多币种 / 国际化？
- [ ] 优惠券系统是独立微服务还是集成在现有订单服务中？

---

## 11. 边界场景汇总

| 场景 | 待确认问题 |
|------|-----------|
| 优惠后金额为0 | 是否允许？是否仍需走支付流程？ |
| 用户下单后未支付就过期 | 券是否仍然有效（以下单时间还是支付时间为准）？ |
| 部分退款 | 优惠金额如何分摊退还？ |
| 全额退款 | 券是否退还？退还后有效期如何处理？ |
| 库存归零 | 用户已加入购物车的券如何处理？ |
| 活动券与新人券身份重叠 | 用户同时满足多种身份条件时如何处理？ |
| 订单金额刚好等于满减门槛 | 是否满足使用条件（>= 还是 >）？ |
| 跨时区用户 | 过期时间以哪个时区为准？ |

---

## 建议优先级

**P0 - 开发前必须明确：**
- 券类型的精确业务规则（第1节）
- 状态流转与退款处理（第2节）
- 叠加规则与适用范围（第3节）
- 并发控制方案（第6节）

**P1 - 设计阶段需明确：**
- 发放机制（第4节）
- 拆单分摊逻辑（第5节）
- 后台管理需求（第8节）

**P2 - 可迭代补充：**
- 用户体验优化（第7节）
- 风控策略（第9节）
- 非功能性需求细化（第10节）
