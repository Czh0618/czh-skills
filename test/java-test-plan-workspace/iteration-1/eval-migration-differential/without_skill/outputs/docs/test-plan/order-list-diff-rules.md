# 订单列表迁移：行为盘点与差异规则

## 1. 行为盘点表（P1 填写）

列：序号 | 位置（文件:行）| 老行为 | JPA 中如何对应 | 命中用例。
没有真实代码，下表只列重点排查项，实际条目要从代码里读出来。

| 排查项 | 为什么容易出差异 |
|---|---|
| `<if test>` 条件写法 | MyBatis 的 OGNL 里数字 0 与空串比较会判为相等，`status != ''` 会让 status=0 被当成没传，不同 MyBatis 版本表现不同。JPA 里判空要显式写，0、false、空串、空白要逐个对 |
| `<where>`、`<trim>` 拼接 | 条件全不传时是否有隐含的默认条件 |
| LIKE 写法 | concat('%', #{x}, '%') 不转义 % 和 _；新实现如果加了 escape 行为就变了 |
| `${}` 拼接 | 排序字段多半是 `${}`，老实现对非法值的反应（报错、忽略、被注入），新实现的白名单要对齐 |
| 分页插件 | PageHelper 等：页码起点、越界页处理、pageSize 上限、count 语句是否裁掉 join |
| 其他插件与拦截器 | 数据权限、租户、逻辑删除条件可能在拦截器里追加，XML 里看不到。JPA 里必须有等价条件 |
| 联表与去重 | 一对多 join 产生重复行，老 SQL 是否 distinct 或 group by；JPA 的 fetch join 加分页会变成内存分页 |
| 排序稳定性 | 没有二级排序键时并列顺序由数据库决定，两条 SQL 执行计划不同，顺序可能不同 |
| resultMap | typeHandler、枚举映射、嵌套关联、null 与默认值；实体转 DTO 后字段是 null 还是空集合 |
| 类型与格式 | BigDecimal 精度、日期格式与时区、Long 转 JSON、null 字段输出还是省略 |
| NULL 与比较语义 | = null、IN 空列表（老实现可能直接 SQL 报错）、不等于遇到 NULL 行 |
| 大小写与 collation | 字符串比较和 LIKE 是否区分大小写取决于库，两边必须走同一库同一列 |
| 延迟加载 | JPA 懒加载在序列化时触发 N+1 或 LazyInitializationException |
| 缓存 | 老实现有无二级缓存、Redis 缓存；比对时关闭或隔离 |
| 异常出口 | 参数校验失败、SQL 异常被全局异常处理器转成什么响应 |

## 2. 差异分级与处置

| 级别 | 定义 | 默认处置 |
|---|---|---|
| A 行集合差异 | 返回的行或 total 不同 | 阻塞，按回归修新实现；确属老 bug 的转 D |
| B 异常差异 | 状态码、错误码、错误体不同，或一边报错一边成功 | 阻塞，处置同 A |
| C 字段差异 | 同一行的字段值、null 或缺省、格式、精度不同 | 逐类处置，同类差异合并成一条 |
| D 老行为疑似 bug | 老实现行为不合理但一直在线上 | 不由测试方决定，列出请你拍板：保持一致还是修正。未拍板前新实现保持与老一致 |
| E 顺序差异 | 行集合相同，仅顺序不同。区分排序键并列内的先后，和排序键不同却乱序 | 并列内按主计划第 7 节 Q5 的口径；非并列阻塞 |
| F 性能差异 | 延迟或 SQL 条数劣化 | 超出阈值则阻塞 |
| G 噪声 | 耗时、trace id、生成时间等天然不同的字段 | 归一化忽略，忽略清单需你过目 |

## 3. 比对规则

- 先比 HTTP 状态码与错误码，再比 total、page、size，再按顺序逐行逐字段比。
- 顺序严格比较，不先排序再比，否则会漏掉排序类回归。
- 归一化只允许：G 类字段、JSON 键顺序、数值等价表示。其他一律算差异。
- 每个差异记录：请求原文、请求形态签名、老响应片段、新响应片段、差异路径。
- 同一形态签名下的差异合并计数，便于分诊。

## 4. 覆盖度度量

- 请求形态覆盖：日志里每种参数形态的数量，与回放抽样数量。
- 分支覆盖：盘点表每个条件分支和隐式条件是否被命中。依据是回放时抓取老实现实际执行的 SQL，按条件片段归类统计。
- 回放后仍未命中的行，回到主计划第 5 节补用例，不要凭猜测认为没人用。
- 日志窗口之外的行为（季度、年度活动期）日志无法覆盖，这条风险写进结论。
