1. `isGreaterThanOrEqualTo(1)` 等于把「幂等」这条需求从测试里删掉。refund 表出现 2 条，说明同一个退款请求并发提交时确实被处理了两次。这是退款，重复记录很可能对应重复打款。每 5 次出现 1 次，是测试在稳定地报告一个真实的并发缺陷，不像测试数据或环境的噪音。放宽后 mvn verify 变绿，缺陷仍在，只是变成发版后由线上用户来触发。
2. `Thread.sleep(3000)` 对这个失败没有帮助。我的假设是两个并发请求各自通过了去重判断后各插入了一条，这是竞态，等待不会让已经写入的第二条记录消失，只会让测试慢 3 秒。
3. `@RepeatedTest` 不是「重试到过」。它是把测试跑 N 次，每次都要通过，任何一次失败整体仍然失败。要失败重试需要 surefire 的 `rerunFailingTestsCount`，那同样会把真实缺陷洗成 flaky 通过，我不建议用在这个测试上。
