# 订单部分退款 测试计划（草案，待评审）

> 范围：POST /api/orders/{id}/refunds（接口契约已确认）。
> 目标项目无代码可查（项目根为空），状态枚举、错误码、表结构、既有幂等约定均查不到；依赖这些的预期结果标「待确认」，不猜、不默认。
> 本文件只定场景与验收条件，不含实现；评审通过前不写任何实现代码。

## 1. 需求拆解

### 1.1 用户流程
- F1 对已支付且未发货的订单发起部分退款并成功
- F2 同一订单多次部分退款，直到累计达到实付金额
- F3 同一个退款请求重复提交

### 1.2 验收标准（需求明写）
- R1 只有已支付且未发货的订单可以退款，其他状态拒绝
- R2 单次退款金额不能超过订单实付金额
- R3 多次部分退款累计不能超过订单实付金额
- R4 退款成功后回补库存
- R5 退款成功后回写订单状态（具体值需求未写，见 Q1）
- R6 同一个退款请求重复提交只生效一次

### 1.3 推导规则（需求未明写，不阻塞评审，由评审人决定是否纳入）
- D1 同一订单并发退款，累计仍不超额
- D2 退款金额必须大于 0，负数、零、超出币种精度的金额拒绝
- D3 订单不存在返回对应错误；他人的订单不可退（数据权限）
- D4 退款与库存回补、订单状态回写要么全成功要么全回滚，不出现「钱退了库存没补」的半成功态
- D5 同一幂等请求并发同时到达，仍只生效一次

### 1.4 待确认（代码里查不到或属于业务决策，需用户/需求方回答）
- Q1 退款后订单状态用哪个值？部分退款与累计退满是否对应不同状态？R5 的预期结果依赖此项。
- Q2 「同一个退款请求」怎么判定？客户端传幂等键（放 header 还是 body）？还是按订单加金额判定？重复提交时返回什么：原样返回首次结果，还是报错？
- Q3 按金额部分退款时库存回补多少？按金额比例、按商品行，还是累计退满才整单回补？
- Q4 「退款成功」是否包含调用支付渠道？渠道同步还是异步，渠道失败怎么处理？
- Q5 已支付、未发货对应的状态枚举值，部分退款后的订单能否继续退款，错误码清单。
