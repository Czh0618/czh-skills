**计划的思路**

老实现跑了 3 年、行为说不清，所以「正确」只能定义成「和老实现的实际输出一致」。计划共 16 个场景：

- 差分 5 个：DIFF-01 回放脱敏生产流量；DIFF-02 随机条件组合，补日志没覆盖的；DIFF-03 定向边界（空值、区间、越界页、非法排序字段、LIKE 特殊字符）；DIFF-04 一对多关联的重复行与 total；DIFF-05 性能（耗时、SQL 条数、N+1，迁移场景默认纳入）。
- E2E 3 个：只测接口契约、典型路径和错误码，边界值不在这一层重复。
- 属性 3 个：分页遍历无重复无遗漏、追加条件结果是原结果子集、同请求幂等。
- 单元 5 个：模糊匹配、区间、排序、分页、隐含过滤（软删除、租户、数据权限）。

回放的几个关键设计：

- 基线不直接用日志里的老响应，而是老实现在同一份测试数据上现跑，避免数据不同造成假差异。
- 归一化只抹字段顺序、空白、traceId 这类无关项；行顺序、total、null 与缺省、数值精度都不归一化。
- 差异按模式聚类后交给裁决人，裁决前一律算未通过，不默认算新代码的问题。已批准差异入清单，每条配一个固定行为的测试。
- 未脱敏的生产数据不能回放，只在测试环境跑。
